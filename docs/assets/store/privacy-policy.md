# Privacy Policy / 隐私政策

**Last updated: 2026-08-17**

> This policy describes how the **Juso (双面搜)** browser extension ("the extension") handles data. The extension is a Bring-Your-Own-Key (BYOK) search aggregator: it lets you query AI search providers you have paid for, and switch queries between those providers and conventional search engines.

---

## English

### 1. Data we collect

The extension **does not collect, transmit, or sell** any analytics, telemetry, usage statistics, or tracking data. There is **no advertising, no affiliate code, no third-party analytics SDK** (no Google Analytics, no Mixpanel, no Sentry, no PostHog, etc.), and the extension never reads your browsing history, cookies, or device identifiers.

The only data the extension stores is:

- **Your own API keys** for the AI search providers you configure (Tavily, Exa, Brave, Stepfun (REST + MCP), Jina, Doubao (web + global)).
- **Your preferences** — the active search source, source ordering and visibility, source groups (grouping, collapse, and pinned layout), per-provider result counts (maxResults), provider instances (multiple named configs per provider, each with its own options), the SERP switch-bar position (top/inline/bottom/auto), UI language, UI theme (light/dark/auto), visual style, any user-saved Site Engines (site-scoped searches with no API key required), and any user-saved custom search engines (URL templates with a `%s` placeholder, no API key required).
- **A local search-result cache** — recent successful search results stored per-device to avoid billing you twice for the same query.

### 2. How data is stored

All data is kept only in `chrome.storage.local` on **your device**. It is **never synced** to your browser account (no `storage.sync`) and is **never logged** to the console or any external service.

**Your API keys are read exclusively by the extension's background service worker** and are never read by any extension page or content script. UI pages and the SERP content script may read only the non-sensitive UI preferences (theme, style, language) for fast first paint.

### 3. How your data is used

- Your **API key** is sent **only to the single search provider you have selected**, **only when you submit a search**, as an `Authorization` or `x-api-key` header. The request also includes the search query and minimal parameters the provider's API requires (such as the requested result count and whether to include an AI-generated answer). For the Stepfun Step Plan MCP surface, the standard MCP `initialize` handshake transmits a static client name and version string (`juso-search`). The MCP client is hard-coded to call only the static `web_search` tool; it does not discover or execute arbitrary remote tools.
- Your **search query** is sent to your selected provider to fulfill the search.
- **Cached results** stay on your device and are reused only for your repeat searches.

### 4. Configuration export / import

You can export a configuration backup file (JSON) from the options page. **This file contains your provider API keys in plaintext**, plus your preferences. The file is generated by the background worker (so keys never enter any page's memory) and is written only when you explicitly request an export, via a system save dialog. The file is **yours**: it is stored wherever you choose, is unencrypted, and is not transmitted anywhere by the extension. Treat it as sensitive. Importing a file fills only empty key slots and optionally applies preferences, with a preview-confirm flow.

Separately, you can download an **Agent Skill package** (a ZIP containing a Python CLI and reference docs) from the options page. This package lets a local AI assistant call the extension's search capability over the Agent Bridge. It contains no API keys or personal data — only code and documentation. It is likewise generated by the background worker and written only when you explicitly request it.

### 5. Agent Bridge (optional, off by default)

The extension includes an **optional** Agent Bridge feature, **disabled by default**. When you explicitly enable it in the options page, it lets **your own local AI assistant** (for example, a locally-run coding agent) invoke the extension's search capability over a **loopback interface** (`127.0.0.1`) so the agent can run searches through your already-configured providers **without ever receiving your stored API keys**.

The bridge is a short-lived, single-request channel: each invocation uses a fresh local port and a single-use token, grants exactly one bounded and validated request, and then disappears. It is not a persistent local API and exposes no stored secrets. All loopback traffic stays on your device.

The bridge supports five actions:

1. **Provider search** — search through one of your configured AI providers (available when the Agent Bridge is enabled).
2. **List configured providers** — return which providers you have configured (no keys).
3. **Engine extraction** — **requires a second, separate opt-in** ("Allow reading public search-engine results"), also off by default. When enabled, the agent can ask the extension to open **one background tab** to any supported engine's result page (Google, Bing, Baidu, Yandex, DuckDuckGo, Bilibili, Xiaohongshu, or Douyin) for a given query, read only the **publicly-rendered result metadata** (titles, URLs, snippets) via a content script, close the tab, and return that data to the local agent. For Bilibili, Xiaohongshu, and Douyin, extraction runs in your own browser profile exactly as loaded (which may be logged in), and only the rendered public result metadata is read. The browser loads the search-engine page exactly as if you had opened it; no additional data is collected from or sent to that page beyond the query in the URL.
4. **Instance search** — search through a specific named provider instance (a saved multi-config of a provider, e.g. different search scenarios or filter options), when you have created more than one config for a provider.
5. **List instances** — return the named provider instances you have configured (no keys).

Actions 4 and 5 are the multi-instance variants of actions 1 and 2; they expose no additional data beyond what those already do.

### 6. Content scripts on search-engine and AI chat pages

On the result pages of conventional search engines (Google, Bing, Baidu, Douyin, Xiaohongshu, Bilibili, Yandex, DuckDuckGo), the extension runs two narrowly-scoped content scripts:

- The **switch-bar** script injects a single switch bar inside a closed shadow root, plus small `<style>` elements that only make room for the bar — repositioning the engine's own toolbar on Baidu and Douyin in inline mode, or adding top/bottom padding to the page in overlay modes (removed when the bar unmounts; no override on other engines). It reads only the DOM anchors needed to place the bar and the query from the URL; it does **not** read account, personal, or form fields, does not modify the search results themselves, and does not send page content anywhere.
- The **extractor** script reads only the natural result metadata (titles, URLs, snippets) the engine has already rendered, and only when the background worker requests it (for the optional engine-extraction action above). It is passive otherwise.

On the pages of supported **AI conversation engines** (ChatGPT, DeepSeek, Doubao, Gemini), the extension runs a third content script — the **AI injector** — only when you switch a query to that AI engine. It fills the current query into the chat input field and, if you have enabled auto-submit, dispatches a submit action. It reads and writes only the input field and the URL query; it does **not** read cookies, stored credentials, account data, or your conversation history, and it sends nothing externally.

No content script on any of these pages reads cookies, stored credentials, account data, or personal identifiers, and none transmits page content to any external server.

### 7. Right-click context-menu search

The extension adds its own submenu to the browser's right-click context menu. It appears **only when you right-click selected text** on a page (selection context) and lists your search sources mirroring the quick-switch bar layout. Clicking an item sends **only the text you selected** to the search source you chose and opens the result in a new tab. The extension does **not** read the page you are on — no URL, no cookies, no other page content — and nothing is sent to the page. The menu is rebuilt when the extension starts, is installed or updated, or your source configuration changes.

### 8. Remote code

The extension does **not** use remote code. All JavaScript is bundled into the extension package. There are no external `<script>` references, no external module imports, and no `eval` or `new Function` string evaluation.

### 9. Children's privacy

The extension is not directed to children and does not knowingly collect data from children.

### 10. Changes

We may update this policy. Material changes will be reflected by the "Last updated" date above.

### 11. Contact

For privacy questions, open an issue in the extension's source repository.

## 中文

### 1. 我们收集的数据

本扩展**不收集、不传输、不出售**任何分析、遥测、使用统计或追踪数据。**无广告、无联盟代码、无第三方分析 SDK**(无 Google Analytics、无 Mixpanel、无 Sentry、无 PostHog 等),扩展**绝不读取**您的浏览历史、Cookie 或设备标识。

扩展存储的唯一数据是:

- **您自备的 AI 搜索 provider API 密钥**(Tavily、Exa、Brave、Stepfun（REST + MCP）、Jina、Doubao（web + global）)。
- **您的偏好**——激活来源、来源排序与显隐、来源分组(分组、折叠与置顶布局)、每来源结果数量(maxResults)、provider 实例(同一 provider 的多套命名配置,各自带独立选项)、快切栏栏位(顶部/内联/底部/自动)、界面语言、主题(浅色/深色/自动)、视觉样式,以及您保存的站外搜索（Site Engine，无需 API 密钥的站点范围搜索）与自定义搜索引擎（带 `%s` 占位符的网址模板，无需 API 密钥）。
- **本地搜索结果缓存**——近期成功的搜索结果按设备缓存,避免对同一查询重复向您计费。

### 2. 数据的存储方式

所有数据仅保存在您设备的 `chrome.storage.local` 中。**绝不同步**到浏览器账号(不使用 `storage.sync`),也**绝不记录日志**到控制台或任何外部服务。

**您的 API 密钥仅由扩展的 background service worker 读取**,任何扩展页面或内容脚本都绝不读取。UI 页面与 SERP 内容脚本仅可读取非敏感的 UI 偏好(主题、样式、语言),用于快速首屏渲染。

### 3. 数据的使用方式

- 您的 **API 密钥**仅发往**您所选的唯一 provider**,且**仅当您提交搜索时**发送,作为 `Authorization` 或 `x-api-key` 头。请求还包含搜索查询与 provider API 所需的最少参数(如结果数量、是否生成 AI 回答)。对 Stepfun Step Plan MCP 接口,标准 MCP `initialize` 握手会发送静态客户端名与版本号(`juso-search`)。MCP 客户端硬编码只调用静态 `web_search` 工具,不发现或执行任意远程工具。
- 您的**搜索查询**发往所选 provider 以完成搜索。
- **缓存结果**仅留在您设备上,仅用于您的重复搜索。

### 4. 配置导出/导入

您可以从设置页导出配置备份文件(JSON)。**该文件以明文形式包含您的 provider API 密钥**及您的偏好。文件由 background worker 生成(因此密钥绝不进入任何页面内存),且仅在您明确请求导出时通过系统保存对话框写入。该文件**归您所有**:存储在您选择的位置,未加密,扩展绝不将其传输到任何地方。请将其视为敏感文件。导入文件时仅填充空的密钥槽位,并可选地应用偏好,且有预览-确认流程。

此外,您可以从设置页下载一个 **Agent Skill 技能包**(ZIP,内含 Python CLI 与参考文档),让本地 AI 助手通过 Agent Bridge 调用扩展的搜索能力。该包不含任何 API 密钥或个人数据,仅含代码与文档;同样由 background worker 生成,且仅在您明确请求时写入。

### 5. Agent Bridge(可选,默认关闭)

扩展包含一个**可选的** Agent Bridge 功能,**默认关闭**。当您在设置页显式开启时,它允许**您自己的本地 AI 助手**(例如本地运行的编程 agent)通过 **loopback 接口**(`127.0.0.1`)调用扩展的搜索能力,使 agent 能通过您已配置的 provider 执行搜索,**却绝不接收您存储的 API 密钥**。

该桥接是短暂的单请求通道:每次调用使用新的本地端口与一次性 token,仅授予一个有界且经验证的请求,随即消失。它不是持久的本地 API,也不暴露任何存储的密钥。所有 loopback 流量均留在您设备上。

该桥接支持五种操作:

1. **Provider 搜索**——通过您配置的某个 AI provider 搜索(启用 Agent Bridge 后可用)。
2. **列出已配置 provider**——返回您已配置哪些 provider(不含密钥)。
3. **引擎抽取**——**需要单独的二次确认开启**("允许读取搜索引擎公开结果"),同样默认关闭。开启后,agent 可请求扩展针对某查询**在后台打开一个标签**到任意受支持引擎(Google、Bing、百度、Yandex、DuckDuckGo、哔哩哔哩、小红书或抖音)的结果页,通过内容脚本**仅读取公开渲染的结果元数据**(标题、网址、摘要),然后关闭标签,将数据返回给本地 agent。对哔哩哔哩、小红书与抖音,抽取在您自己的浏览器配置中按原样运行(可能处于已登录状态),仅读取渲染出的公开结果元数据。浏览器加载该搜索引擎页面的方式与您亲自打开完全一致;除 URL 中的查询外,不从该页面收集或向其发送任何额外数据。
4. **实例搜索**——通过某个具名 provider 实例(同一 provider 的多套配置,如不同搜索场景或过滤方向)搜索,仅当您为某 provider 创建了多套配置时可用。
5. **列出实例**——返回您已配置的具名 provider 实例(不含密钥)。

第 4、5 项是第 1、2 项的多实例变体,不额外暴露任何数据。

### 6. 搜索引擎与 AI 对话页面上的内容脚本

在常规搜索引擎(Google、Bing、百度、抖音、小红书、哔哩哔哩、Yandex、DuckDuckGo)的结果页上,扩展运行两个范围严格的内容脚本:

- **快切栏**脚本在闭合 shadow root 内注入一行快切栏,并注入小幅 `<style>` 仅为快切栏腾出空间——内联模式在百度与抖音上仅位移引擎自身工具栏,覆盖层模式(顶部/底部)则为页面添加对应方向的内边距(卸载时移除;其余引擎无样式覆盖)。它仅读取用于定位快切栏的 DOM 锚点与 URL 中的查询;**不读取**账号、个人或表单字段,不修改搜索结果本身,不向任何地方发送页面内容。
- **抽取**脚本仅读取引擎已渲染的自然结果元数据(标题、网址、摘要),且仅当 background worker 请求时(用于上述可选的引擎抽取操作)。其余时间被动。

在受支持的 **AI 对话引擎**(ChatGPT、DeepSeek、豆包、Gemini)页面上,扩展运行第三个内容脚本——**AI 注入器**——仅当您把查询切换到该 AI 引擎时触发。它把当前查询填入对话输入框,并在您开启自动提交时派发提交动作。它仅读写输入框与 URL 查询;**不读取** Cookie、已存凭据、账号数据或您的对话历史,不向任何外部发送数据。

这些页面上的内容脚本均不读取 Cookie、已存凭据、账号数据或个人标识,均不向任何外部服务器发送页面内容。

### 7. 右键菜单搜索

扩展在浏览器右键菜单中添加自己的子菜单。它**仅在您右键选中文字时**出现(selection 上下文),列出与快切栏布局一致的搜索来源。点击某项时,仅将**您选中的文字**发送给您选择的搜索来源,并在新标签页中打开结果。扩展**不读取**您所在的页面——不读 URL、不读 Cookie、不读任何其他页面内容,也不会向该页面发送任何数据。菜单在扩展启动、安装或更新,或您的来源配置变化时重建。

### 8. 远程代码

本扩展**不使用**远程代码。所有 JavaScript 均打包进扩展包。无外部 `<script>` 引用、无外部模块导入、无 `eval` 或 `new Function` 字符串执行。

### 9. 儿童隐私

本扩展不面向儿童,也不 knowingly 收集儿童数据。

### 10. 政策变更

我们可能更新本政策。重大变更将通过上方"最后更新"日期体现。

### 11. 联系方式

如有隐私问题,请在扩展源代码仓库提 issue。
